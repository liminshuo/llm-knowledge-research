llms.txt 与机器入口

机器发现层决定爬虫与 Agent 从哪条 URL 开始、抓哪类载体——不是单页正文质量，而是站点是否声明 canonical 源。 本页以站点配置实测 + 三模型检索 URL 分布，论证昇腾社区缺少 llms.txt、屏蔽源路径、sitemap 只索引渲染页的后果。

核心问题
  • 无机器发现层：/llms.txt 返回 404；未声明机器友好出口、主推版本与章节索引，Agent 只能沿用人类浏览路径。
  • 最优源被主动屏蔽：robots.txt 含 Disallow: /doc_center/，与 交付格式 结论（source 4–11 KB 为最佳载体）直接冲突。
  • 发现层索引渲染页：sitemap 抽样 10,000 条 URL 100% 为 /document/detail/，零条 doc_center；与 检索阶段 观测一致，加剧 多版本消歧 困难。

测试问题

站点是否为机器层声明了可抓取的 canonical 入口？若未声明，爬虫与联网检索实际会落在哪类 URL？

站点配置实测

2026-06-07 对 hiascend.com 根路径三类机器发现文件做 HTTP 探测。完整命令见 hiascend-discovery-probe.md。

论证链
发现层缺失 → 只暴露渲染页 → 检索池版本分散 → 生成无法「最新版优先」。机器入口是把 交付格式 · 噪声 与 时效 问题在源头收敛的配置层。

改进目标

在站点根提供机器发现层：明确 canonical 源路径、当前主推版本、章节索引与废弃版本——使合规爬虫与联网 Agent 默认落在低噪声机器层，而非 224KB 渲染页。

改进措施

一、部署 llms.txt（P0）

遵循 llms.txt 规范，在根路径提供机器可读索引；配套可提供 llms-full.txt 展开全站章节。

# /llms.txt > Ascend C 算子开发 · CANN 社区版 9.0.0 - [机器层 MD 出口](https://.../ascend-c-900.md) - [源 HTML 根路径](https://.../doc_center/source/.../900/...) - [当前主推版本说明](https://.../version-policy) - [废弃版本索引](https://.../deprecated)

二、调整 robots.txt（P0）

  • 放行 /doc_center/source/（或单独 Allow 规则），与「推荐抓 source」一致
  • 保留对 /profile/ 等无关路径的 Disallow
  • 在 robots 注释或 llms.txt 中交叉引用机器层入口

三、sitemap 与 canonical 策略（P1）

  • sitemap 增加机器层 URL，或单独 sitemap-machine.xml
  • 对 910beta / 8.x 标注 deprecated 或降低优先级
  • 主推版本 900 在发现层显式声明为 canonical

四、与双轨交付衔接（P0）

llms.txt 是发现层，交付格式 · 双轨交付 是内容层——二者配套。入库后字段消歧见 元数据 · 解决方案。
