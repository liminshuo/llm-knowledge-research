机器发现层缺失

机器发现层即 llms.txt、robots.txt、sitemap 等站点配置，告诉爬虫和 Agent：该从哪条 URL 抓、主推哪一版文档。 它缺失时，机器只能沿人类浏览路径抓到高噪声渲染页，落不到最优机器源。

问题实测

1. 向模型提问

我想让 AI 自动读昇腾社区文档，站点有没有告诉爬虫该从哪抓？实际联网检索一般会落到哪类页面？

2. 大模型回答

查看大模型回答内容

3. 问题洞察

大模型的回答指向两点结论：

  • 站点没告诉爬虫从哪抓：llms.txt 返回 404、robots.txt 屏蔽 /doc_center/、sitemap 100% 只列渲染页——机器友好入口与主推版本均未声明。
  • 抓取默认落在高噪声载体：Agent 只能沿人类浏览路径，落到 ~224 KB 的 /document/detail/ 渲染页，而非纯净的 /doc_center/source/ 机器源。

结果是合规抓取拿不到最优机器源，进而加剧 格式噪声 与 多版本混淆。

根因分析

发现层缺失的核心原因是：无 llms.txt / llms-full.txt 机器索引、robots 屏蔽机器源、sitemap 只引导渲染页、页级机器入口缺失。

1. 无机器索引声明

/llms.txt 与 /llms-full.txt 均返回 404——前者缺站点级索引与主推版本，后者缺全库 Markdown 聚合入口，Agent 只能沿用人类浏览路径。

修改建议

部署 llms.txt（声明索引、机器源基址与主推版本 900）与 llms-full.txt（聚合 source Markdown 全文，供 Agent 单次加载）。

2. robots 屏蔽机器源

robots.txt 含 Disallow: /doc_center/，合规爬虫抓不到源 HTML / PDF（详见 格式交付）。

修改建议

调整 robots.txt，放行 /doc_center/source/。

3. sitemap 只引导渲染页

sitemap 抽样 10,000 条 URL 均为 /document/detail/ 渲染页，零条 doc_center，多版本无优先级。

修改建议

完善 sitemap：优先收录机器源 URL，旧版标注 deprecated 或降优先级。

4. 页级机器入口缺失

全站 <head> 未声明 link rel="llms"，单篇渲染页也无可见的机器可读入口（页脚示例见 格式交付）。

修改建议

全站 <link rel="llms" href="/llms.txt">，与 双轨交付、页级元数据 配套落地。
