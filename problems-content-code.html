代码语义 部分可抓

代码语义指代码块的语言类型、文件名、纯净源码文本对模型是否可读——HelloWorld 等页代码主体可获取，但 highlighttable 将行号混入代码文本。 以 HelloWorld 为例：缺少 language-xxx 标注，且引号等符号若以 HTML 编码留在代码里，入库后源码不能直接编译使用。

3. 问题洞察

大模型的回答指向两点结论：

  • 代码主体可抓、语义劣化：highlighttable 将行号与代码混为表格单元格，入库后出现 1 2 3… 行号前缀，复制后不能直接编译。
  • 语言与场景未标注：无 language-xxx 标注，bash / C++ / CMake 易混淆；HTML 实体未解码。

根因分析

代码语义劣化的核心原因是：行号混入源码、无 language 标注、HTML 实体未解码。

1. 行号污染源码

highlighttable 布局将行号写入 code 文本节点。

修改建议

行号由 CSS 渲染，弃用表格布局承载代码。

2. 无 language 标注

pre > code 未标明语言，模型难区分 Ascend C / bash / CMake。

修改建议

标注 class="language-cpp" 等，块上方注明文件名与场景。

3. HTML 实体残留

&quot; 等实体留在入库源码里，不能直接编译。

修改建议

管道入模前还原 HTML 实体为可读字符。

4. 场景上下文缺失

代码块与说明步骤的从属关系在 chunk 中丢失。

修改建议

代码块上方注明上下文（如 hello_world.asc、CMake 编译场景）（见 代码块语义化）。
