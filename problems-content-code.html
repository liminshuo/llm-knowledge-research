代码语义

代码语义指代码块的语言类型、文件名、纯净源码文本对模型是否可读。HelloWorld 等页代码主体可获取，但 highlighttable 将行号混入代码文本，且缺少 language-xxx 标注；非激活 Tab 内的代码还可能被隐藏遗漏。

部分可抓
核心问题
  • highlighttable 将行号与代码混为表格单元格，入库后出现 1 2 3…31 行号前缀，干扰代码复用与精确检索
  • 未标注 class="language-xxx"，模型难以区分 bash / C++ / CMake / Ascend C 源码
  • HTML 实体（&quot; 等）未解码时进一步污染代码 chunk；全站 Tab 组件中非激活面板内的代码还可能完全缺失（见 Tab 隐藏）

测试问题

读取 HelloWorld（CANN 9.0.0），hello_world.asc 核函数代码前几行是什么？复制出来的代码有没有 1 2 3 行号前缀？bisheng 与 CMake 命令分别是什么语言？

结论：代码主体可抓，语义劣化

代码内容能进入知识库，但不够「可复用」。用户问「贴出 hello_world.asc 头文件 include」时，模型可能返回带行号污染的文本；问「CMake 编译命令」时，正文虽默认可见，但可能因无 language 标注而与 bash 命令混淆。

1. highlighttable 行号污染

HelloWorld 页将代码行号与源码混为 highlighttable 两列：左列 linenos、右列 code。转文本时行号数字与代码合并，出现如下污染：

<table class="highlighttable"> <tr> <td class="linenos"><pre>1\n2\n3...</pre></td> <td class="code"><pre>// Host侧...#include "acl/acl.h"</pre></td> </tr> </table>

典型抓取结果：

1 2 3 // Host侧应用程序需要包含的头文件
#include "acl/acl.h"

行号前缀使代码无法直接编译运行，也干扰「精确匹配代码片段」类检索。

2. 语言类型未标注

代码块缺少 class="language-cpp" / language-bash" / language-cmake" 等标注。模型输出时难以区分：

代码片段实际语言入库后问题
hello_world.asc 核函数Ascend C / C++无 language 标注，与 bash 命令混淆
bisheng hello_world.asc ...bash未标 language-bash
cmake_minimum_required...CMake无 language-cmake 标注

3. 表格语义滥用

将代码拆入表格单元格，使表格语义与代码语义混杂——详见 表格与列表结构语义。环境准备页的 cmake 安装命令结构较简洁，亲和度相对较好，可作对照标杆。

4. Tab 隐藏导致的代码遗漏（全站风险）

HelloWorld 的 bisheng / CMake 代码以列表并列默认展示，非 Tab 隐藏场景。全站其他章节的非激活 Tab 面板内，代码块可能因 display:none 完全不在输出中——见 Tab 隐藏，与行号污染等问题可叠加。

入库状态对照

入库环节代码语义状态说明
代码主体文本部分可抓逻辑内容可获取
行号分离污染入库1 2 3… 前缀混入
语言标注缺失无 language-xxx
文件名 / 场景标注缺失未标 hello_world.asc、bisheng 场景
非激活 Tab 内代码完全丢失display:none 跳过
HTML 实体解码视管道而定&quot; 可能残留

改进目标

让每段代码以纯净、带语言标注、可独立检索的 chunk入库——用户检索「hello_world.asc include」「bisheng 编译命令」时能返回可直接复用的代码，LLM 引用时不含行号噪声。

改进措施

一、内容侧：代码规范化（P0，治本）

核心原则：代码语义先行入库——源码与行号分离，语言与文件名显式标注。详见 亲和原则 · 代码语义。

做法入库效果
1 置于 <pre><code class="language-xxx">（CODE-01） 模型识别 bash / cpp / cmake
2 行号与代码分离，行号不写入 code 文本（CODE-02） chunk 可直接复制运行
3 不使用 highlighttable 拆分代码（CODE-03） 表格语义不再污染代码
4 标注文件名、语言、适用场景（CODE-04） 可检索「hello_world.asc」「bisheng 编译」
5 HTML 实体解码后再入模型层（CODE-06） " 等符号正确还原

hello_world.asc 改造示例

❌ 当前：highlighttable + 行号污染

<table class="highlighttable"> <tr><td class="linenos">1 2 3</td> <td class="code"><pre>// code...</pre></td></tr> </table>

知识库 chunk：1 2 3 // Host侧... — 不可直接编译。

✅ 改造后：pre + code + 元数据

<div class="code-block" data-filename="hello_world.asc" data-language="asc"> <pre><code class="language-cpp">// Host侧应用程序需要包含的头文件 #include "acl/acl.h" #include "kernel_operator.h" ...</code></pre> </div>

知识库 chunk：纯净源码，可检索文件名与语言。

机器层 Markdown 输出要点

```cpp // 文件：hello_world.asc #include "acl/acl.h" ... ``` ```bash # 使用 bisheng 编译 bisheng hello_world.asc --npu-arch=dav-2201 -o demo ```

二、架构侧：双轨交付 + 转换管道

双轨交付与转换管道——人类层保留语法高亮与行号 UI，机器层输出纯净代码块：

HTML 源（doc_center） │ ├──► 人类层：highlighttable + 行号 UI（体验不变） │ └──► 机器层：MD / JSON └── highlighttable → 提取 code 列，剥离 linenos └── 标注 ```language + 文件名 └── Tab 内代码全展开后独立成块

行号剥离在发布转换环节完成，而非指望模型自行忽略数字前缀。
