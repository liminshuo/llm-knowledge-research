代码语义 部分可抓

代码语义指代码块的语言类型、文件名、纯净源码文本对模型是否可读——HelloWorld 等页代码主体可获取，但 highlighttable 将行号混入代码文本。 以 HelloWorld 为例：缺少 language-xxx 标注，且引号等符号若以 HTML 编码留在代码里，入库后源码不能直接编译使用。

核心问题
  • highlighttable 将行号与代码混为表格单元格，入库后出现 1 2 3…31 行号前缀，干扰代码复用与精确检索
  • 未标注 class="language-xxx"，模型难以区分 bash / C++ / CMake / Ascend C 源码
  • 引号等符号若以 &quot; 这类 HTML 编码形式留在代码里，入库后源码不能直接编译使用

问题实测

测试问题

读取 HelloWorld（CANN 9.0.0），hello_world.asc 核函数代码前几行是什么？复制出来的代码有没有 1 2 3 行号前缀？bisheng 与 CMake 命令分别是什么语言？

结论：代码主体可抓，语义劣化

代码内容能进入知识库，但不够「可复用」。用户问「贴出 hello_world.asc 头文件 include」时，模型可能返回带行号污染的文本；问「CMake 编译命令」时，正文虽默认可见，但可能因无 language 标注而与 bash 命令混淆。

解决方案

改进目标

让每段代码以纯净、带语言标注、可独立检索的 chunk 入库。

改进措施

  • 必要行号与代码分离：行号由 CSS 渲染，不写入 code 文本节点；弃用 highlighttable 表格布局承载代码；
  • 必要language-xxx 标注：pre > code 须标明语言类型（如 language-cpp、language-bash、language-cmake）；
  • 可选文件名/场景标注：代码块上方注明上下文信息（如：hello_world.asc、CMake 编译场景）；
  • 可选HTML 实体解码：管道入模前将 &quot; 等 HTML 实体还原为可读字符。

核心原则：代码语义先行入库——源码与行号分离，语言与文件名显式标注。详见 亲和原则 · 代码语义。
