单文档结构边界

对应研究概览第 8 节「信息架构与跨页语义」的页内维度：标题层级、列表嵌套、Tab / 折叠与切片边界——页内结构在渲染层清晰，抓取后 chunk 边界错乱或从属关系丢失。

边界错乱
核心问题
  • 标题层级（H1–H6）整体清晰，但部分页面存在空段落作间距，干扰 chunk 边界
  • Tab / 折叠导致页内结构在机器层扁平化失败——模型看到的顺序与人类阅读顺序不一致
  • 代码块、表格、提示之间的从属关系（如「安装 CANN」步骤下的注意提示）在渲染层清晰，抓取后可能丢失嵌套语义
  • Topic 锚点 ID（ZH-CN_TOPIC_xxx）存在且稳定，但未在机器层作为切片边界显式标注

问题实测

测试问题

以 环境准备（CANN 9.0.0） 为例，入库后能否回答：

  • 某条注意提示属于安装流程的哪一步？
  • CANN 软件下载页 Tab 中「我不知道硬件信息」折叠面板的内容是否在 chunk 中？
  • 按 H2/H3 切片时，代码块会不会被拦腰截断？

结论：页内结构边界未稳定保留

对人类是层级清晰的文档，对 RAG 是扁平或错序的文本块。 空段落制造伪边界、Tab 只入库默认态、步骤内 Note 被抽离——检索「安装注意事项」时可能召回孤立提示，却看不出它依附于哪一步。

1. 空段落与伪 chunk 边界

部分页面用空 <p> / <br> 控制间距。管道按段落切分时产生空白 chunk或打断标题与正文邻接，向量召回出现噪声、上下文连贯性下降。

2. Tab / 折叠：页内顺序与人类不一致

CANN 软件下载页 Tab 与「我不知道硬件信息」折叠面板（见 Tab 语义、折叠语义）在 UI 层组织信息，默认抓取往往只保留默认 Tab 态或跳过 display:none 区域——与用户实际阅读路径不一致。

结构要素典型问题入库后后果
Tab 面板仅默认态入库隐藏分支内容不可召回
折叠面板display:none 被跳过硬件选型指引等语义丢失
步骤内 NoteDOM 层级被扁平化提示与步骤从属关系丢失
Topic 锚点 ID存在但未标注切片无法精确定位章节

3. 列表嵌套与从属关系

环境准备页等用有序列表表达安装步骤时结构良好；但若用多个独立段落模拟步骤、或将 Note 与步骤拆成不相邻块，抓取后步骤序号与提示绑定断裂。代码块、表格若跨 chunk 插入无关元素，从属小节同样难以还原。

入库状态对照

入库环节页内结构状态说明
标题层级 H1–H6基本可用多数页层级清晰
Tab / 折叠全量展开未落实隐藏语义见专项页论证
步骤—提示 DOM 嵌套不稳定依赖页面写法，管道未统一保留
Topic ID 切片标记缺失锚点存在但未用于 chunk 边界

解决方案

改进目标

页内标题、列表、提示与代码块的层级与邻接关系在源码与管道层可感知——chunk 按 H2/H3 + Topic ID 稳定切分，Tab / 折叠全量展开，步骤内 Note 不脱离所属条目。

改进措施

规范源码：间距与列表结构 P0

  • 禁止用空 <p> / <br> 堆叠代替段落间距——用 CSS margin 控制版式，避免伪 chunk 边界。
  • 步骤与层级用 <ol> / <ul> 表达，不用多个独立段落模拟列表——管道可稳定识别条目边界。
  • 代码块、表格、提示与所属步骤 / 小节保持 DOM 邻接——避免跨块插入无关元素。

标注切片边界：Topic ID 与标题层级 P0

  • 保留稳定锚点 ID（如 ZH-CN_TOPIC_xxx），管道将其作为 chunk 切片边界标记。
  • 标题层级规则（H1–H6 不跳级）见 元数据字段规范 · 标题规则——与切片策略一致。
  • RAG 按 H2/H3 边界切片，表格整张入库、代码块不拦腰截断（衔接 知识库集成）。

落实管道：保留嵌套、展开隐藏语义 P0

  • 嵌套在 <ol><li> 内的 Note 保留 DOM 层级——抓取时不扁平化（见 注意提示语义）。
  • Tab 各面板、折叠各区块在机器层全量扁平展开为 H3 小节——顺序与人类阅读路径一致（见 Tab、折叠）。
  • 转换管道在 HTML→MD 步骤中统一落地上述规则，而非依赖渲染页剥壳猜测。

核心原则：页内结构即切片契约——源码怎么嵌套，chunk 就怎么入库。详见 亲和原则 · 单文档结构感知。
