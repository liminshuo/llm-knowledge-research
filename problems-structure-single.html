单文档结构边界 边界错乱

单文档结构边界指一篇页面内部的标题层级、列表嵌套、步骤与提示的从属——人读得清，chunk 切出来也要对。 以 环境准备 为例：标题大多清晰，但空段落、Tab/折叠默认态、步骤内 Note 扁平化会让入库块边界错乱或从属丢失。

核心问题
  • 空 <p> / <br> 当间距——管道切 chunk 时产生空白块或打断标题与正文
  • Tab / 折叠只入库默认态（详见 Tab、折叠）——页内阅读顺序与机器读到的不一致
  • 步骤内的注意提示 DOM 嵌套良好，抓取后可能与步骤断联；Topic 锚点 ID 存在但未用于切片

问题实测

测试问题

我在看 环境准备（CANN 9.0.0），文档里的「注意」提示具体对应安装流程哪一步？按章节切分后，步骤里的代码和说明会不会被拆开读乱？

结论：页内结构边界未稳定保留

对人类是层级清晰的文档，对 RAG 可能是扁平或错序的文本块。 空段落制造伪边界、步骤内 Note 被抽离、Tab 只保留默认态——检索「安装注意事项」时可能召回孤立提示，却看不出依附于哪一步。

Topic ID 切片标记缺失锚点存在但未写入 chunk

解决方案

改进目标

页内标题、列表、提示与代码块的层级与邻接在源码和管道层可感知——chunk 按 H2/H3 + Topic ID 稳定切分，Tab / 折叠全量展开，步骤内 Note 不脱离所属条目。

改进措施

  • 必要规范列表结构：步骤用 <ol> / <ul>，禁止空 <p> 堆间距；
  • 必要标注切片边界：保留 Topic 锚点 ID，按 H2/H3 切片；表格整张入库、代码块不拦腰截断；
  • 必要保留嵌套语义：步骤内 Note 保留 DOM 层级（见 注意提示）；
  • 必要展开隐藏语义：Tab / 折叠在机器层全量展开为 H3 小节（见 Tab、折叠）；
  • 可选代码块、表格、提示与所属步骤保持 DOM 邻接，避免跨块插入无关元素。

核心原则：页内结构即切片契约——源码怎么嵌套，chunk 就怎么入库。详见 亲和原则 · 单文档结构感知。
