图片图意 未入库

图片图意指信息型图片所承载、但未写成正文的文档语义——知识库入库时应转写为可检索、可引用的文本 chunk。 以 什么是 Ascend C 为例：若仅入库 PNG 文件名或图片二进制，API 分层、成长地图阶段等图意视为未入库。

核心问题
  • 6 张信息型 PNG 在转文本管道中完全不出现在 chunk 中——图意对人类可见，对 RAG 不可见
  • 解析 HTML 仅见 zh-cn_image_xxx.png 文件名，无 alt 与内容转写
  • 下载 PNG 直链 ≠ 图意入库——除非额外接入视觉模型，否则不会产生可召回 chunk

问题实测

测试问题

我在看 什么是 Ascend C（CANN 9.0.0），能帮我解释一下里面的 Ascend C 层级架构图吗？

结论：图意未入库

即便能获取到图片文件地址，图意仍无法进入知识库。在默认 RAG 及网页 Reader 管道下，当用户提问「Ascend C API 有几层」「学习路径分几阶段」时，知识库中没有对应 chunk 可被召回——图片中的信息对人类可见，但对检索系统不可见。

图片类型页面上入库后

入库环节状态说明

图意转写（alt + 描述）源站缺失文档未提供
PNG 直链下载不等价入库须文本化转写

解决方案

改进目标

让图片图意以文本 chunk 的形式进入知识库——使用户检索「API 分层」「成长地图阶段」时能召回对应语义，LLM 引用时有据可依；此方案不要求在线看图，但要求图意事先完成转写。

改进措施

  • 必要alt：在 <img> 上写有意义说明（如「API 层级架构图」），而非 zh-cn_image_xxx.png；
  • 必要图片内容转写：将节点、层级、箭头关系写成正文——渲染页须有可见等价物（图下「图片内容转写」段落，或成长地图用正文 <ol> 列表）；
  • 必要装饰图标标记 aria-hidden 或改为文本，纯装饰 PNG 从渲染页移除；
  • 可选架构 / 流程图提供 Mermaid / SVG 可编辑源，入库时优先解析替代不可读 PNG。
