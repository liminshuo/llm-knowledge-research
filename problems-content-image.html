图片图意

图片图意指信息型图片所承载、但未写成正文的文档语义——层级结构、学习阶段划分、卡片主题与意图等。知识库入库时，这些内容应被转写为可检索、可引用的文本 chunk；若只入库 PNG 文件名或图片二进制，则视为图意未入库。

未入库
核心问题
  • 信息型图片的图意（API 分层关系、成长地图阶段、卡片主题）无法成为可检索 chunk——对人类可见，对 RAG 不可见
  • 实测「什么是 Ascend C」：6 张信息型 PNG 在转文本管道中完全缺失，HTML 解析仅见 zh-cn_image_….png 文件名，源站普遍无 alt、无内容转写
  • 图片直链可下载，但 PNG 本身不产生可召回语义；检索「API 有几层」「成长路径分几阶段」时知识库无对应 chunk

问题实测

测试问题

读取 什么是 Ascend C（CANN 9.0.0），你能读取里面的图片吗？

结论：图意未入库

能拿到图片文件地址，但图意无法进入知识库。默认 RAG / 网页 Reader 管道下，用户问「Ascend C API 有几层」「学习路径分几阶段」时，知识库中没有对应 chunk 可召回——图里的信息对人类可见，对检索不可见。

1. 常规抓取 → 图意 chunk 不存在

页面转 Markdown / 纯文本时，只能得到正文段落（Ascend C 定义、API 分层文字列表、产品型号等）。6 张信息型 PNG 完全不在输出里——不是「图意劣化」，而是知识库中根本没有承载这些语义的文本块。

2. 解析 HTML → 只见文件名，不见图意

即使深入解析 HTML，正文区 6 张信息型图片也几乎无可用语义字段：

图片HTML 特征入库后可见内容
API 层级架构图 zh-cn_image_0000002531512958.png，无 alt 无意义文件名；分层关系未转写
成长地图 zh-cn_image_0000002562432937.png，带 usemap 文件名 + 坐标热区；阶段标题与意图未转写
核心原理 / API 参考 / 算子实践卡片图（4 张） 均带 usemap，无 alt 卡片主题与入口意图未转写

典型抓取结果仅为：

<img usemap="#d90300e79" src=".../zh-cn_image_0000002562432937.png">

对向量检索与 LLM 引用而言，这等价于空白 chunk。

3. 未提供文本等价物

以下语义只存在于图片像素中，当前文档未提供文本等价物，入库后即丢失：

图片丢失的图意
API 层级架构图C API → 基础 API → 高阶 API → 算子模板库 → PyAsc 的分层与从属关系
成长地图五行学习阶段、每阶段卡片标题、学习意图与先后次序
核心原理 / API 参考 / 算子实践卡片图各模块卡片主题、视觉分组与入口意图

正文虽有 API 分层列表，但与架构图的结构关系（嵌套、箭头、分组）并不等价；成长地图的阶段路径在正文中亦无完整文字表述。

4. 下载 PNG ≠ 图意入库

图片直链可访问（HTTP 200），例如：

https://www.hiascend.com/doc_center/source/zh/CANNCommunityEdition/900/programug/Ascendcopdevg/figure/zh-cn_image_0000002562432937.png

但「入库」要求图意变成可检索文本。除非额外接入视觉模型转写或多模态向量索引（属 P3 补救路径），否则 PNG 文件本身不会自动产生「API 分层图」「成长地图五阶段」等可召回 chunk。

入库状态对照

入库环节图意状态说明
正文段落已入库定义、列表等文字语义可检索
信息型 PNG（转文本管道）完全丢失图片不出现在 chunk 中
信息型 PNG（解析 HTML）完全丢失仅见文件名，无 alt / 转写
图意转写（alt + 内容描述）源站缺失文档未提供，管道无法生成

解决方案

改进目标

让图片图意以文本 chunk进入知识库——用户检索「API 分层」「成长地图阶段」时能召回对应语义，LLM 引用时有据可依。不要求在线看图，要求图意事先转写完毕。

改进措施

1. 推进内容侧：图意文本化 P0

  • 信息型图片必须有 alt——产生基础 chunk：「API 层级架构图」「Ascend C 成长地图」，至少可检索到图的存在与类型。
  • 复杂图附「图片内容转写」——产生高价值 chunk：层级列表（C API → 基础 API → … → PyAsc）、成长地图五阶段标题与意图。
  • 针对架构图、层级图：优先 Mermaid / SVG，可解析代码入库，附内容转写。
  • 装饰图标 aria-hidden——避免无意义 PNG 稀释正文 chunk 密度。

核心原则：图意先行入库——图里承载什么结构、层次、阶段，页面上必须有可被抓取的文本等价物。详见 亲和原则 · 图片图意。

成长地图转写要点

除 alt 外，用正文列表写出每阶段标题、学习目标与推荐顺序——使「学习路径」语义不依赖读图：

## Ascend C 学习路径（成长地图转写） 1. 了解概念 — 什么是 Ascend C、编程模型概述 2. 环境准备 — 安装 CANN、配置环境变量 3. …

热区跳转链接的文本冗余属链接维度，见 链接语义 页；与图意转写配合使用，但不替代图意本身。

2. 落实架构侧：双轨交付

针对成长地图、阶段路径图：正文列表转写阶段标题与意图。双轨交付——人类层保留 PNG 视觉体验，机器层预置图意转写：

HTML 源（doc_center） │ ├──► 人类层：PNG + 热区 + 交互 UI（体验不变） │ └──► 机器层：MD / JSON + llms.txt └── 每张信息型图 → alt + 内容转写 chunk └── 架构图优先 Mermaid / SVG 源

RAG 只消费机器层；图意入库在发布环节完成，而非检索时临时「看图」。
