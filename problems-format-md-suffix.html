.md 后缀 ≠ Markdown

社区 .md URL 与纯 Markdown 源文件的本质区别。

要点二：社区 .md 后缀与 Markdown 是一回事吗？

结论
不是同一种东西。 昇腾社区 9.1.0-beta.1 的 .md URL 是「URL 命名约定 + 前端 MD 渲染管线」，不等于交付给爬虫的纯 Markdown 源文件。
概念是什么交付物模型读到什么
纯 Markdown 文件 .md 后缀的静态文本文件，内容为 Markdown 语法 纯文本，如 # 标题\n\n正文 完整、低噪声、可预测 ✅
llms.txt 推荐的 .md Companion 与 HTML 页同 URL 追加 .md，返回真实 MD 副本 静态 Markdown 文件（规范意图） 应与 HTML 正文等价 ✅
昇腾社区 .md URL URL 以 .md 结尾，但由 Nuxt SPA + MD 组件渲染器输出 ~211 KB 的 HTML 页面（含全站壳层） 出现 [object Object]、链接丢失 ❌
三种「.md」的本质区别 ① 纯 Markdown 源文件 ② llms.txt 规范的 .md Companion ③ 昇腾社区 .md URL ┌─────────────────┐ ┌─────────────────┐ ┌─────────────────┐ │ # 什么是Ascend C │ │ # 什么是Ascend C │ │ Nuxt SPA 壳层 │ │ 正文 Markdown… │ │ 正文 Markdown… │ │ + MD 渲染组件 │ │ （静态 .md 文件）│ │ （静态 .md 文件）│ │ + [object Object]│ └─────────────────┘ └─────────────────┘ └─────────────────┘ 模型友好 ✅ 模型友好 ✅ 模型不友好 ❌ 真正的 Markdown 规范意图中的形态 只是 URL 后缀叫 .md

为什么社区 .md URL 不是 Markdown？

  • 响应体仍是 HTML — curl 抓取返回的是完整 HTML 文档（~211KB），不是 text/markdown 纯文本
  • 走 SPA 渲染管线 — Markdown 源先被前端 MD 组件解析，再嵌入 Vue 组件树，最终输出 DOM；爬虫拿到的是渲染结果而非源文件
  • 组件序列化失败 — 嵌入的 React/Vue 对象无法被文本爬虫读取，输出为 [object Object]
  • 命名误导 — URL 后缀暗示「这是 Markdown」，使开发者和 RAG 系统误判为低噪声源，实际可能比 .html 更差
