格式交付与抓取入口 劣化入库

交付格式决定爬虫读到的是纯净正文，还是带全站导航的 200KB+ 渲染壳层。 以 什么是 Ascend C 实测：.md URL 名不副实、渲染页噪声大，而 /doc_center/source/（4–11 KB）才是当前最佳载体——但机器入口未声明。

3. 问题洞察

大模型的回答指向三点结论：

  • 机器没有稳定低噪声入口：默认爬虫落在 ~224 KB 渲染页，/doc_center/source/（4–11 KB）虽最优却未声明。
  • .md 名实不符：.md URL 仍走 Nuxt SPA，实测出现 [object Object]、锚文本丢失——扩展名不能当「模型友好」依据。
  • 双轨缺失：人类看渲染页，机器层没有稳定的 MD / source 并行出口（见 机器发现层）。

根因分析

交付载体不适配的核心原因是：双轨缺失、.md 名实不符、source 路径未声明、默认抓渲染壳层。

1. 双轨缺失

人类层有渲染页，机器层无并行 MD / source 出口——RAG 默认剥 224 KB 壳层。

修改建议

同源双发：doc_center/source/ 与渲染页并行，管道导出 MD / JSON。

2. .md 扩展名误导

.md URL 仍走 SPA，管线成熟度低于同页 .html。

修改建议

澄清后缀不等于真实 Markdown，禁止把 .md URL 当机器层入口。

3. source 未声明

/doc_center/source/ 被 robots 屏蔽，sitemap / llms.txt 未引导——合规爬虫抓不到。

修改建议

部署 llms.txt、放行 source 路径（见 机器发现层）。

4. 页级机器入口缺失

单篇渲染页无可见「机器可读版本」链接。

修改建议

页脚提供 source / MD 入口，与 双轨交付 配套。
