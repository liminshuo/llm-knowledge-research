格式交付与抓取入口 劣化入库

交付格式决定爬虫读到的是纯净正文，还是带全站导航的 200KB+ 渲染壳层。 以 什么是 Ascend C 实测：.md URL 名不副实、渲染页噪声大，而 /doc_center/source/（4–11 KB）才是当前最佳载体——但机器入口未声明。

核心问题
  • 双轨缺失：人类看 /document/detail/ 渲染页，机器层没有稳定的低噪声 MD / source 并行出口
  • .md 名实不符：.md URL 仍走 Nuxt SPA，实测出现 [object Object]、锚文本丢失——扩展名不能当「模型友好」依据
  • source 存在但未声明：/doc_center/source/ 正文纯净，但 robots 屏蔽、无 llms.txt——合规爬虫默认抓渲染页（见 机器发现层）

问题实测

测试问题

我在看 什么是 Ascend C（CANN 9.0.0），想保存这篇入门介绍——浏览器地址改成 .md 和 .html，读到的内容一样吗？

结论：机器没有稳定的低噪声入口

默认爬虫落在 200KB+ 渲染页，.md 扩展名还会误导。 同篇正文在不同 URL 下读到不同信息；最优 source 路径存在，却没有在站点配置里声明给 Agent。

解决方案

改进目标

人类层保留现有渲染页；机器层通过同源双发获得纯净 MD / JSON——RAG 与 Agent 只消费机器层，不再默认剥 224 KB 渲染壳层。

改进措施

  • 必要双轨交付：doc_center/source/ 与渲染页并行发布，管道导出 MD / JSON；
  • 必要机器消费规则：抓取 source 或 Markdown 源，禁止默认抓带全站导航的渲染页；
  • 必要澄清 .md URL：后缀不等于真实 Markdown 文件，须在文档中明确区分；
  • 必要站点发现层：部署 llms.txt、放行 source 路径（见 机器发现层）；
  • 可选页脚「机器可读版本」链接，指向本篇 source 或 MD 入口。

核心原则：同源双发——人类要交互，机器要纯净。详见 亲和原则 · 格式交付。
