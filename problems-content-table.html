表格与列表结构语义

表格与列表结构语义指行列关系、表头含义、列表嵌套层级对模型是否可读。标准数据表（如「表1 编程模型分类」）是四页中亲和度标杆；问题出在 highlighttable 误用于代码行号、部分表格缺 caption，以及嵌套列表 + 注意提示抓取后扁平化丢失从属关系。

两极分化
核心问题
  • 「编程模型概述」页「表1 编程模型分类」结构完整（★★★★★），但 HelloWorld 将代码行号混为 highlighttable——表格语义被滥用
  • 部分表格缺乏 <caption> 或前置标题，模型难以理解表格主题与检索上下文
  • 环境准备页列表嵌套注意提示结构良好，但抓取后嵌套从属关系可能扁平化，步骤与提示的层级语义弱化

测试问题

读取 编程模型概述（CANN 9.0.0），SIMD / SIMT / AI CPU 三种编程模型分别适用于什么计算空间？再对比 HelloWorld 页代码区——表格结构是否被误用？

结论：标杆与滥用并存

标准数据表亲和度极高，表格滥用则严重劣化代码语义。用户问「三种编程模型计算空间」时，编程模型概述页可准确召回；问「贴出 hello_world 源码」时，highlighttable 使表格结构与代码文本混杂。

1. 标杆：表1 编程模型分类

编程模型概述页表格具备完整语义要素：

要素现状入库效果
<caption>「表1 编程模型分类」主题可检索
<th> 表头编程模型 / 计算空间 / 特点列语义清晰
行列数据SIMD→AI Core、SIMT→AI Core 等结构完整

该页为四页诊断中唯一 ★★★★★ 完整度，表格是核心贡献因素。

2. 滥用：highlighttable 充当代码容器

HelloWorld 页用 highlighttable 承载代码行号——表格语义与代码语义混淆，详见 代码语义：

<table class="highlighttable"> <tr><td class="linenos">行号列</td> <td class="code">代码列</td></tr> </table>

违反 TBL-03「不在单元格内嵌套代码块」——代码应独立于表外，行号由 CSS 渲染。

3. caption 缺失的表格

部分页面表格仅有视觉样式表头，无 <caption> 或前置「表 N」标题。入库后 chunk 缺少表格主题上下文，向量检索「表1」「编程模型分类」等锚点困难。

4. 嵌套列表 + 注意提示扁平化

环境准备页将注意提示嵌套在 <ol><li> 步骤内，源 HTML 结构良好。但部分转文本管道将列表与提示压平为连续段落，「安装 CANN」步骤与其下「注意：set_env.sh」的从属关系弱化——影响 注意提示 与步骤的联合检索。

对比：两类表格入库效果

表格类型典型页面入库效果
标准数据表（tablenoborder）编程模型概述 · 表1结构完整
highlighttable（代码行号）HelloWorld语义滥用
无 caption 数据表部分参考页主题不明

入库状态对照

入库环节表格/列表状态说明
标准数据表（有 caption + th）已入库行列语义完整
highlighttable 代码区语义滥用表格≠数据表
无 caption 表格劣化入库缺主题锚点
有序列表步骤已入库步骤序列可检索

机器层 Markdown 表格源站缺失未额外输出 MD 表

改进目标

让每张数据表以带 caption、表头明确的结构化 chunk入库；列表保持嵌套层级；代码不再占用表格单元格。检索「编程模型分类」「SIMD 计算空间」时能准确召回表格语义。

改进措施

一、内容侧：表格与列表规范化（P0，治本）

核心原则：表格表达数据、列表表达层级，代码独立于表外。详见 亲和原则 · 表格。

做法入库效果
1 表格必须有 caption 或前置标题（TBL-01） chunk 含「表1 编程模型分类」锚点
2 表头 <th> 明确（TBL-02） 列语义不依赖 CSS
3 不在单元格内嵌套代码块（TBL-03） 代码归 代码语义 维度
4 机器层额外输出 Markdown 表格（TBL-04） LLM 可直接解析 pipe 表
5 列表嵌套提示时保持 <li> 完整展开（P-01） 步骤与注意提示从属清晰

表1 编程模型分类（保持标杆）

<table> <caption><b>表1 </b>编程模型分类</caption> <thead> <tr><th>编程模型</th><th>计算空间</th><th>特点</th></tr> </thead> <tbody>...</tbody> </table>

highlighttable 改造方向

❌ 当前：代码在行号表格内 → 表格语义污染。

✅ 改造：代码移出表外，改用 pre > code；行号仅人类层 CSS 渲染。

机器层 Markdown 输出要点

**表1 编程模型分类** | 编程模型 | 计算空间 | 特点 | |----------|----------|------| | SIMD编程 | AI Core | 适合矩阵计算、连续计算的矢量算子... | | SIMT编程 | AI Core | 适用于离散访问场景... | | AI CPU编程 | AI CPU | 作为 AI Core 计算的补充 |

二、架构侧：双轨交付 + 切片策略

架构侧双轨交付与知识库切片策略——整张表作为一个切片单元，不拆分行列：

HTML 源（doc_center） │ ├──► 人类层：表格样式 + 行号 UI（体验不变） │ └──► 机器层：MD / JSON └── 数据表 → caption + MD 表格 + JSON 数组 └── highlighttable → 剥离为独立代码块（非表格） └── 列表嵌套结构保留缩进层级
