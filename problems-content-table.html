表格的结构语义 语义劣化入库

表格的结构语义指行列关系、表头含义对模型是否可读。 Add 自定义算子 · 表1 设计规格则代表复杂规格表——有表题但列布局混杂、空单元格与伪多行列表并存。

核心问题
  • Add 算子 · 表1 Ascend C Add算子设计规格：表题可见但非 caption 语义；5 列网格大量空单元格；「使用的主要接口」拆成 4 行伪数据行——入库后 API 列表与算子规格从属关系易丢失

问题实测

测试问题

我在看 Add 自定义算子开发（CANN 9.0.0），表 1 里输入 x 的 shape 和 dtype 是什么？核函数叫什么？主要用到哪些接口？

结论：复杂规格表语义劣化入库

表1 含完整算子规格，但行列从属需靠位置推断。用户问「x 的 shape」「DataCopy 接口」时，正文可召回；问「表1 Add 算子设计规格包含哪些 API」时，接口列表与 OpType 从属在 chunk 中易断开——表题非 <caption>、5 列空网格与接口伪多行是主因。

解决方案

改进目标

让 表1 Ascend C Add算子设计规格 以带 caption、分区子表与独立接口列表的结构化 chunk 入库。检索「Add 算子 x shape」「DataCopy 接口」「表1 Add算子设计规格」时能准确召回表格语义与从属关系。

改进措施

针对 Add 表1 的结构问题，在 doc_center/source 与渲染页中补充表格结构字段：

  • 必要表题 / caption：「表1 Ascend C Add算子设计规格」须写入 <caption>，入库后可作为检索锚点；
  • 必要<th> 表头：I/O 子表的 name / shape / data type / format 须使用 <th>，禁止样式伪装的 <td>；
  • 必要接口列表独立化：「使用的主要接口」改为 <ul> 或合并单元格，禁止拆成 4 行伪数据行；
  • 可选机器层 Markdown 表格：为规格表额外输出 MD 副本，保留 I/O 行列与接口列表结构。

核心原则：规格表 = caption + I/O 子表 + 接口列表，避免 5 列空网格混排。详见 亲和原则 · 表格的结构语义。
