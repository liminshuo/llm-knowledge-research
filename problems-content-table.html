3. 问题洞察

对照表 1 规格与用户提问，指向两点结论：

  • 规格表语义劣化：表 1 含完整算子规格，但行列从属需靠位置推断——接口列表与 OpType 从属在 chunk 中易断开。
  • 表题未结构化：「表 1 Add 算子设计规格」未写入 <caption>，问「表 1 包含哪些 API」时难以锚定。

根因分析

表格语义劣化的核心原因是：无 caption、th/scope 缺失、嵌套列表拆成伪数据行。

1. 表题未声明

表题不在 <caption> 里，入库后失去检索锚点。

修改建议

表题写入 <caption>，如「表 1 Ascend C Add 算子设计规格」。

2. 表头语义缺失

I/O 子表用样式伪装的 <td> 承载表头——行列关系入库后劣化。

修改建议

使用 <th> + scope 表达行列关系。

3. 接口列表嵌在单元格

「使用的主要接口」拆成多行伪数据行，与 OpType 从属断开。

修改建议

接口列表改为 <ul> 或合并单元格独立呈现。

4. 机器层无 MD 副本

复杂规格表在 HTML 入库后结构进一步Flatten。

修改建议

为规格表额外输出 Markdown 表格副本（详见 表格语义化）。
