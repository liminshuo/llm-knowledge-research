检索阶段 官方信源感知弱

检索阶段指三模型联网问答中为回答当前问题而访问的 URL 池（非知识库 chunk 召回）。 本页统计该池中昇腾社区（hiascend.com）官方 URL 占比。

核心结论
  • 社区官方占比偏低：Claude 21%、DeepSeek 33% 均未过半；千问界面未显示检索链接。
  • 非社区信源占主导：Claude 第三方 79%；DeepSeek 华为系其他渠道 56%——与「基于官方资料」约束错位。

问题实测

测试问题

Claude AI · DeepSeek · 千问

解决方案

改进目标

提升检索阶段昇腾社区官方 URL 的占比，同时确保拉取的内容为低噪声机器层（doc_center/source/ 或声明的 Markdown 出口），而非高噪声的渲染页及旧版路径。

改进措施

  • 必要补充机器发现层：针对官方占比偏低（如 Claude 仅 21%），部署 llms.txt，声明 canonical 源与主推版本 900；通过 sitemap 引导官方机器层，避免 Agent 自行猜测入口（详见 机器发现层 · 解决方案）；
  • 必要落实双轨交付与格式：针对第三方教程主导问题，官方文档以机器层 Markdown / 源 HTML 并行发布，提升官方 Markdown 的可索引性与排序权重，使联网检索优先暴露低噪声 URL（详见 格式交付 · 解决方案）；
  • 可选强化版本与元数据过滤：针对检索 URL 版本混杂，主推版本 900，旧版路径标注「已弃用」；入库携带 version 字段，检索默认过滤 CANN 9.0.0（详见 版本滞后 · 解决方案、页级元数据 · 解决方案）。
