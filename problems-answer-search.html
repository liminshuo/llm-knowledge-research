检索阶段

检索阶段即大模型在生成回答前、通过联网搜索拉取的网页池。 本页只聚焦这一阶段：统计三模型检索结果中，来源于「昇腾社区」官方（hiascend.com）的 URL 占比。

核心结论
  • 昇腾社区占比分化：千问脚注参考链接 54%（13 条中 7 条）最高，DeepSeek 33%（27 条中 9 条），Claude 仅 21%（19 条中 4 条）最低；三模型检索阶段对官方社区文档的覆盖差异显著，直接决定后续生成能否优先召回 hiascend.com 内容。
  • 非社区信源主导：Claude 检索池 79% 为第三方教程，DeepSeek 华为系渠道合计 56%（开发者 30% + 云博客 26%），昇腾社区并非二者检索主来源；联网检索更易拉入教程站与华为系页面，削弱「基于官方资料」prompt 的可执行性。

测试问题

「基于官方资料，介绍一下 Ascend C 算子开发」（三模型同 prompt）

来源类型说明

  • 昇腾社区官方

    URL 含 hiascend.com，如 /document/detail/ 文档页、/doc_center/source/ 源文件、/developer/techArticles/ 技术文章、/ascend-c 学习入口等昇腾社区站点内容。

  • 其他官方渠道

    华为体系内、但域名不是 hiascend.com 的官方文档与社区，如 developer.huawei.com 文档 / 论坛 / Codelabs、e.huawei.com 等。

  • 第三方教程

    非华为 / 昇腾官方的独立教程与资讯站，如知乎专栏、CSDN、博客园、阿里云开发者、中关村在线等。

  • 其他来源

    既非昇腾社区、也非典型第三方教程站的边缘来源，如华为云社区博客（bbs.huaweicloud.com）等。

改进目标

提升检索阶段昇腾社区官方 URL 占比，并确保拉取的是低噪声机器层（doc_center/source 或声明的 MD 出口），而非高噪声渲染页与旧版路径。

改进措施

一、机器发现层（P0）

部署 llms.txt 声明 canonical 源与主推版本 900，避免 Agent 自行猜测入口。详见 llms.txt · 解决方案。

二、双轨交付与格式（P0）

官方文档以机器层 MD / 源 HTML 并行发布，联网检索排序时优先暴露低噪声 URL。详见 交付格式 · 解决方案。

三、版本与元数据过滤（P1）

入库标注 version，检索默认过滤 CANN 9.0.0，降低 8.x / 850 商用 / beta 路径被拉入检索池的概率。详见 元数据 · 解决方案、版本滞后 · 解决方案。
