跨页关系未结构化 语义未结构化

跨页关系指章节之间的 breadcrumb、上下篇、父主题——人读页面能看清位置，chunk 之间却没有可检索的关系边。 以 什么是 Ascend C 为例：路径挤在 <title> 里、上下篇未进 Front Matter——检索「环境准备」时分不清所属教程线。页级 version / doc_id 见 页级元数据未结构化。

核心问题
  • 同名「环境准备」缺乏 breadcrumb 消歧——模型难判断属于入门教程还是软件安装
  • 多版本文档并存，跨页关系未与 version 绑定，检索时版本混淆
  • 上下篇、父主题链接页面上可见，机器层未标准化为 prev / next / parent_topic

结论：跨页关系未结构化

人类在渲染页能看见章节位置，RAG 读不到关系边。 breadcrumb 压缩在 <title> 字符串里、上下篇未进 Front Matter——chunk 之间没有可检索的 prev / next / parent_topic，多跳推理与学习顺序推理失败。

解决方案

改进目标

每篇 chunk 入库时附带Level 1 跨页关系——breadcrumb、上下篇、父主题与版本绑定可检索；同时剥离 Level 3 全站导航，避免 282 项侧栏稀释正文。

改进措施

  • 必要定义页级身份：明确 version、doc_id、applicable_devices 等字段（见 页级元数据）；
  • 必要绑定跨页关系：渲染页展示完整 breadcrumb、页脚或文首「上一篇 / 下一篇」，机器层写入 prev / next / parent_topic；
  • 必要管道同步入库：页面上可见的版本、面包屑等信息须同步写入 chunk 结构化字段，不能仅有视觉可读形式；
  • 必要剥离 Level 3 导航：机器源从 /doc_center/source/ 抓取，自动去除全站侧栏文档树；
  • 可选文章摘要：在文档头部补充 60–120 字摘要，概括本文主题与适用读者。

核心原则：轻量 IA 入库——不是把全站导航树灌进 chunk，而是每篇带上「我在哪、前后是什么」。详见 亲和原则 · 跨文档结构感知。
