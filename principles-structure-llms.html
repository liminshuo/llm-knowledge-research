llms.txt / sitemap 部署

在站点层部署机器发现层（llms.txt、llms-full.txt、sitemap.xml、robots.txt），声明机器应从哪条 URL 抓取、主推哪一版文档。同时在人类浏览页提供可见的「机器可读版本」入口，避免 Agent 与合规爬虫只能沿渲染页路径抓取。 能找到 · 序号 1 · 对应 问题论证 · 机器发现层缺失。

设计侧

机器发现入口位置和样式设计

  • 每个文档页脚增加「机器可读版本」入口，样式与「上一篇 / 下一篇 / 反馈」同级、可识别
  • 入口文案明确指向 source / Markdown 等机器源，而非泛化「分享」或图标按钮

⎘ 机器可读版本（source HTML） · © 昇腾社区 · 上一篇 · 下一篇

研发侧

补充机器发现层

  1. 部署 /llms.txt，按「产品线-版本」分组列出核心文档 URL + 一句话描述
  2. 提供 /llms-full.txt：将索引内文档的 source Markdown 全文聚合为单文件，供 Agent 单次加载上下文（由构建管道从 /doc_center/source/ 自动生成）
  3. /sitemap.xml 优先收录 /doc_center/source/ 等机器源路径
  4. robots.txt 放行 source/ 路径，禁止爬取 /assets/、/api/

llms.txt

机器怎么用：Agent 接到文档相关任务时，先访问 /llms.txt 拿到「该读哪些页」的清单，再按链接去抓具体文档——不用在人类渲染页里自己猜入口。参考样例：Anthropic llms.txt

sitemap.xml（片段）

机器怎么用：搜索引擎爬虫定期读取 /sitemap.xml，按清单里的 URL 依次抓取并建索引——我们把机器源路径优先放进清单，让索引落到干净正文而非渲染页。参考样例：Anthropic sitemap.xml

<url>
  <loc>https://www.hiascend.com/doc_center/source/zh/CANN/900/operator_dev.html</loc>
  <lastmod>2026-06-01</lastmod>
  <priority>0.9</priority>
</url>
<!-- 优先 machine source，而非 /document/detail/ 渲染页 -->

robots.txt（片段）

机器怎么用：爬虫进站先读 /robots.txt，按规则决定哪些路径能抓、哪些要跳过——放行 source/、禁止 /assets/ 等，避免浪费配额抓无关资源；文件末尾的 Sitemap: 行再指向页面清单。参考样例：Anthropic robots.txt

User-agent: *
Allow: /doc_center/source/
Disallow: /assets/
Disallow: /api/
Disallow: /document/detail/   # 可选：引导爬虫走 source 路径

Sitemap: https://www.hiascend.com/sitemap.xml
