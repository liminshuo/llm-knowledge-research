元数据丰富化

为每篇文档补全文档身份、版本、适用产品、更新时间、上下篇关系等元数据，并在页头展示摘要与面包屑，让机器可结构化检索、人可快速定位。 能找准 · 序号 4 · 对应 问题论证 · 页级元数据未结构化。

设计侧

元数据位置和样式设计

  1. 文档身份：文档 id
  2. 版本信息：版本号、版本的发布日期、版本的生命周期状态
  3. 适用产品：适用芯片、设备信息
  4. 更新信息：最后更新日期
  5. 关联与关系：父子文档关系、上一篇 / 下一篇

文档摘要位置和样式设计

  1. 文档摘要：每篇文档前补充摘要，150 个字符以内

内容侧

元数据内容补充

每个文档页面建议在 <head> 中包含丰富的结构化元数据，优先使用 JSON-LD 格式。

研发侧

元数据位置和样式设计

  1. <head> 中输出完整 JSON-LD（BreadcrumbList + TechArticle）
  2. 提供 /docs/{doc_id}/metadata.json 端点供机器读取
  3. prev / next / parent_topic 关系链写入 meta
