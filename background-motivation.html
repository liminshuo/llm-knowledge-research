研究概览

本研究聚焦昇腾社区 Ascend C 官方文档 如何进入大模型 RAG / 知识库。 这些页面原先面向人类开发者设计——依赖视觉层次、图片热区、Tab 交互与品牌化排版； 而知识库入库需要的是可检索、可引用、可跨页推理的完整文档语义，远不止正文段落。

  • 人类阅读注重体验与效率优先：主要场景为快速浏览、热区跳转、Tab 切换、复制代码。
  • 知识库入库，语义尽量完整、噪声尽量剥离：准确将正文、图意、热区链接、代码与表格结构、IA 元数据（版本 / 面包屑 ）进行转写与入库。

同一套源文档需同时回答两个问题：人读得顺，与 机器读得全——后者是本研究的主线。

核心命题 RAG / 知识库尽量完整收录昇腾官方文档的文档语义。

研究范围

整体范围是昇腾官方文档 Ascend C 算子开发。 本研究主要聚焦下列五个典型页面——它们承载不同的组件类型与语义载体，覆盖了后续语义维度中的主要研究对象。

# 页面 组件特征
1 什么是 Ascend C 图片热区、成长地图、API 层级图
2 环境准备 注意提示、嵌套列表、代码块
3 HelloWorld 多代码块、编译分支、设备型号提示
4 Add 自定义算子开发 流程示意图（图1–图4）、表1 设计规格、LINK 占位符、多代码块与行号表格、跨页文档链接
5 CANN 软件下载 多轴 Tab 选型（版本、架构、发行版、在线/离线安装）、折叠面板收纳安装步骤与部署命令

语义维度

昇腾官方文档的语义不只存在于正文段落，还分布在图片、热区、链接、交互组件、代码、表格、提示框、页面元数据与版本信息等多层。默认抓取 /document/detail/ 渲染页时，大量语义无法进入 RAG，或被噪声稀释。

  • 语义完全丢失：知识库里根本没有对应 chunk，例如热区 28 条跳转、无 alt 的图意。
  • 语义劣化入库：有文本，但结构或类型被破坏，例如代码带行号、链接写成 LINK。
  • 语义未结构化：页面上有，但未变成可检索元数据，例如 breadcrumb、version、设备型号。

1. 图片语义 语义完全丢失

常规抓取：图意只存在于图片像素里，文档没提供文字等价物，默认管道不会「看图」，所以不会产生可检索正文。

抓 HTML 源码：能读到 <img> 标签，但图意仍进不了库，还需：

  • 必要alt：图片标签上补充图片说明，而非无意义文件名
  • 必要data-llm-transcription：补充图片内容转写，图里的节点、层级、箭头关系都写成正文
  • 可选figcaption：补充图注，如「图1：xxx」这类说明段落
  • 可选title：图片标签上补充可用的标题说明
  • 可选流程图替换图源：如 Mermaid 图源可读取可编辑

当前以抓取 什么是 Ascend C（CANN 9.0.0） 为例，正文区 6 张说明图对向量检索和 LLM 引用而言，等价于空白。具体实测见 问题论证 · 图片图意。

2. 图片热区 语义完全丢失

图片热区在默认抓取 / 默认 RAG 管道下属于语义完全丢失；只有在专门解析 HTML 时才能看到裸 href，但那仍没有可检索的链接语义。除了要补充上文图片语义的字段，热区额外需补充：

  • 必要nav：补充文本链接列表，覆盖全部热区目标
  • 必要area alt / area title：补充热区标签，当前热区中多数无标签，只有坐标与裸 href
  • 必要描述性锚文本：补充 <a> 标签内的文字内容；当前缺阶段名/文档名，仅有文件名
  • 必要绝对 URL：<a href> / <area href> 的属性值须为完整 URL；当前为相对路径，机器层难直接引用与跳转

当前以 什么是 Ascend C（CANN 9.0.0） 页的成长地图为例：单图 14 个热区入口（环境准备、HelloWorld 等）对向量检索和 LLM 引用而言，等价于空白链接。具体实测见 问题论证 · 图片热区。

3. 链接语义 语义劣化入库

占位符链接在默认抓取 / 默认 RAG 管道下属于语义劣化入库：href 会入库，但锚文本不提供目标描述，chunk 中仅出现「LINK」等无意义字样，模型无法推断跳转意图。需补充：

  • 必要描述性锚文本：<a> 内文字须描述目标（如「HelloWorld 完整样例（GitCode）」），禁止「LINK」「点击这里」
  • 可选title：链接标签上可补充用途说明
  • 可选站外来源标注：GitCode 等外链旁附完整域名或 external 标记

当前以抓取 HelloWorld（CANN 9.0.0） 为例：「完整样例请参考 LINK」对向量检索和 LLM 引用而言，等价于无目标语义的链接。具体实测见 问题论证 · 链接语义。

4. 隐藏语义 语义完全丢失

Tab 非激活面板、折叠面板等交互 UI 在默认抓取 / 默认 RAG 管道下属于语义完全丢失：正文存在于 DOM，但被 display:none 等 CSS 隐藏，多数管道不遍历隐藏节点，知识库里无对应 chunk。调整策略为：

  • 必要Tab 全量展开：源 HTML 中各 Tab 面板完整存在，机器层以 H3 扁平输出全部面板（非仅默认 Tab）
  • 必要折叠默认展开：机器层导出时展开全部折叠块，区内步骤、代码、提示一并入库
  • 必要禁止 display:none 藏正文：非激活 Tab 面板、折叠正文不得用 CSS 从管道可见流中移除
  • 可选details open：原生折叠组件建议默认展开，或加 data-llm-expanded

5. 代码语义 语义劣化入库

代码块在默认抓取 / 默认 RAG 管道下属于语义劣化入库：源码逻辑能进 chunk，但 highlighttable 将行号混入代码文本。缺少 language-xxx 标注，模型拿到的代码不可直接复用，也难以区分 bash / C++ / CMake。调整策略为：

  • 必要行号与代码分离：行号由 CSS 渲染，不写入 code 文本节点；弃用 highlighttable 表格布局承载代码
  • 必要language-xxx 标注：pre > code 须标明语言（如 language-cpp、language-bash、language-cmake）
  • 可选文件名 / 场景标注：代码块上方注明 hello_world.asc、编译场景等上下文
  • 可选HTML 实体解码：管道入模前将 &quot; 等实体还原为可读字符

当前以抓取 HelloWorld（CANN 9.0.0） 为例：hello_world.asc 核函数代码入库后出现 1 2 3…31 行号前缀，对向量检索和 LLM 引用而言等价于不可编译的噪声文本。具体实测见 问题论证 · 代码语义。

6. 表格语义 语义劣化入库

标准数据表在默认管道下结构完整、可检索；但 highlighttable 滥用或缺 caption 的表格属于语义劣化入库——行列关系被破坏，chunk 缺表题等主题锚点。调整策略为：

  • 必要表题 / caption：表格上方须有可见主题（如「表1 编程模型分类」），入库后可作检索锚点
  • 必要th 表头：列名用表头单元格标注，不用样式伪装的 td
  • 必要禁止单元格嵌大段代码：代码独立于表格外；highlighttable 不得充当代码容器
  • 可选机器层 Markdown 表格：数据表额外输出 MD 副本，保留行列结构

当前以 编程模型概述（CANN 9.0.0）「表1 编程模型分类」为标杆（★★★★★），对比 HelloWorld 的 highlighttable 代码区——前者行列语义完整，后者表格与代码语义混杂。具体实测见 问题论证 · 表格与列表结构语义。

7. 提示语义 语义劣化入库

「注意提示」在默认抓取 / 默认 RAG 管道下属于语义劣化入库：notebody 正文可入库，但提示类型（注意 / 警告 / 说明）由装饰图标传达，无文本等价物，模型无法区分提示级别，也无法按类型过滤检索。嵌套在步骤列表内的提示若被扁平化，步骤与提示的从属关系亦会丢失。调整策略为：

  • 必要data-admonition-type：源码标注 note / warning / tip / danger 等类型
  • 必要补充文本类型前缀：渲染页用「注意：」「警告：」等文字替代 note_3.0-zh-cn.png 装饰图标
  • 必要机器层引用块（blockquote）：转为 Markdown > **注意** 格式，保留类型与正文
  • 可选补充与步骤从属关系：嵌套在 <ol><li> 内的提示，抓取时保留层级而非扁平化

当前以抓取 环境准备（CANN 9.0.0） 为例：set_env.sh 说明正文可检索，但 chunk 中缺少「注意」类型标签，与普通段落难以区分。具体实测见 问题论证 · 注意提示（Note）类型语义。

8. 信息架构与跨页语义 语义未结构化

面包屑、版本、上下篇、锚点等在渲染页可见，但默认管道只抓正文段落，不进 chunk 元数据——属于语义未结构化。RAG 只能做全文相似度，无法按版本过滤、消歧同名章节或推理学习顺序。调整策略为：

  • 必要定义页级身份：version、doc_id、applicable_devices——回答「哪一版、适用谁」
  • 必要绑定跨页关系：breadcrumb、prev / next、父主题——消歧「环境准备」属于入门教程还是软件安装，并保留章节间跳转
  • 必要管道同步入库：页面上能看到的版本、面包屑等，入库时也要写成 chunk 的结构化字段（如 JSON-LD / Front Matter），不能只有人类能读、向量库里没有
  • 可选文章摘要：头部 60–120 字概括本文主题与适用读者，作检索锚点（当前普遍缺失）

9. 格式交付与抓取入口 语义劣化入库

当前抓 .html / .md 渲染页，均非机器层。壳层入库，语义被淹没。正文 chunk 与页头页脚、全站导航争 token、争向量召回。优先 source 或 markdown。调整策略为：

  • 必要采用双轨交付：人类渲染页与 doc_center/source / markdown 并行发布；
    .md URL 不是真 markdown
  • 必要定义机器消费规则：机器直接抓 doc_center/source 或 markdown，别抓用户浏览器里那套带导航的大页面
  • 必要增强站点发现：部署 llms.txt，放行 doc_center/source/，sitemap 优先收录机器源 URL
  • 可选增加全站索引链接：全局模板在 <head> 增加 <link rel="llms" href="/llms.txt">
  • 可选增加站点 Markdown 入口：渲染页提供「机器可读版本」链到 markdown

10. 信源时效

信源可能来自第三方和旧版本，导致版本错误、非官方内容优先。调整策略为：

  • 必要站点版本外显：页头展示 version 徽章；旧版章节标注弃用并链到替代文档
  • 必要定义版本过滤规则：chunk 入库带 version 字段，RAG 默认过滤 CANN 9.0.0（900）社区版
  • 必要站点主推声明：llms.txt / sitemap 声明 canonical 源与主推 900，减少旧版与 beta 被默认拉入
  • 可选定义溯源输出规则：生成回答脚注附带 version、doc_id 与来源 URL，不只裸链接
