注意提示（Note）类型语义

注意提示类型语义指 note / warning / caution / tip 等提示级别对模型是否可识别。<div class="note"> 内 notebody 正文可获取，但装饰图标 note_3.0-zh-cn.png 无文本——模型不知道这是「注意」还是「警告」，也无法按类型过滤检索。

正文可抓
核心问题
  • 环境准备页 notebody 正文可入库（如 set_env.sh 说明），但提示类型语义丢失——图标 PNG 不产生可检索文本
  • 无 data-admonition-type 等结构化字段，RAG 无法按「注意 / 警告」过滤；LLM 引用时缺少 > **注意** 级别前缀
  • 四页诊断：环境准备 ★★★★☆，主要丢失项即注意图标语义；嵌套在列表步骤内时，从属关系见 表格与列表结构语义

测试问题

读取 环境准备（CANN 9.0.0），安装 CANN 后需要执行什么命令设置环境变量？这条信息是普通正文还是「注意」类提示？能否只检索文档中的「警告」而不混入「注意」？

结论：正文可抓，类型语义缺失

提示正文能进入知识库，但类型不可识别。用户问「set_env.sh 怎么执行」时可召回正文；问「环境准备有哪些注意事项（注意级别）」时，chunk 中缺少类型标签，与正文段落难以区分。

1. notebody 正文 → 可入库

环境准备页典型结构：

<div class="note"> <img src="public_sys-resources/note_3.0-zh-cn.png"> <span class="notetitle"> </span> <div class="notebody">安装CANN软件后...执行 source ${INSTALL_DIR}/set_env.sh...</div> </div>

notebody 内文字可完整抓取——set_env.sh 命令语义可检索。环境准备页完整度 ★★★★☆，正文获取是主要得分项。

2. 图标 → 类型语义为零

提示类型由黄色背景 + note_3.0-zh-cn.png 图标传达，图标无 alt、无文本。入库后模型只见 PNG 路径或空白，无法推断 admonition 类型：

人类感知模型抓取差异
黄色框 + 注意图标 →「注意」note_3.0-zh-cn.png 或无输出类型丢失
警告框 →「警告」同类装饰 PNG不可区分
与步骤的从属关系嵌套在 <li> 内时可保留视管道而定

3. 无结构化类型字段

当前 <div class="note"> 无 data-admonition-type="note"，机器层未转换为 MD 引用块（> **注意**）。后果：

  • 无法按类型过滤检索（「只查警告」）
  • LLM 引用时缺少严重程度信号，可能将「注意」与正文同等对待
  • 与 装饰图标 问题同类——视觉信息未文本化

4. 嵌套在步骤列表内

环境准备页将注意提示嵌套在「安装 CANN 软件包」步骤的 <li> 内，源 HTML 结构亲和。但若列表被扁平化，提示与步骤的从属关系弱化——属 列表结构 维度，与类型缺失叠加。

入库状态对照

入库环节注意提示状态说明
notebody 正文已入库set_env.sh 等可检索
提示类型（注意/警告）完全丢失图标无文本语义
data-admonition-type缺失未结构化标注
MD 引用块转换未执行无 > **注意** 前缀
与步骤从属关系部分保留依赖列表嵌套是否扁平化
装饰图标噪声或空白应 aria-hidden

改进目标

让每条注意提示以带类型标签的结构化 chunk入库——正文可检索，类型可过滤（note / warning / caution / tip），LLM 引用时带 > **注意** 级别前缀，与所属步骤的从属关系保留。

改进措施

一、内容侧：提示类型文本化（P0，治本）

核心原则：类型语义先行入库——图标装饰，文本承载类型。详见 亲和原则 · Note 类型。

做法入库效果
1 data-admonition-type 标注类型（NOTE-01） 可按 note / warning 过滤检索
2 notebody 完整展开（NOTE-02） 正文不依赖图标
3 图标 aria-hidden，类型用文本前缀（NOTE-03） PNG 不稀释 chunk
4 机器层转 MD 引用块（NOTE-04） > **注意** 前缀可识别
5 提示不嵌套折叠（NOTE-05） 避免与 折叠隐藏 叠加

环境准备 set_env.sh 改造示例

❌ 当前：类型不可识别

<div class="note"> <img src="note_3.0-zh-cn.png"> <div class="notebody">安装CANN软件后...set_env.sh...</div> </div>

知识库 chunk：仅有正文段落，无「注意」标签。

✅ 改造后：类型已入库

<aside class="admonition note" data-admonition-type="note" role="note"> <p class="admonition-title">注意</p> <p>安装CANN软件后，使用CANN运行用户进行编译、运行时， 需要执行 <code>source ${INSTALL_DIR}/set_env.sh</code> 设置环境变量。</p> </aside>

知识库 chunk：可检索「注意」「set_env.sh」「环境变量」。

机器层 Markdown 输出要点

> **注意** > 安装CANN软件后，使用CANN运行用户进行编译、运行时，需要以CANN运行用户登录环境，执行 `source ${INSTALL_DIR}/set_env.sh` 命令设置环境变量。

二、架构侧：双轨交付 + 切片绑定

架构侧双轨交付与知识库切片策略——注意提示与上下文步骤绑定切片，不脱离所属步骤：

HTML 源（doc_center） │ ├──► 人类层：黄色框 + 图标 UI（体验不变） │ └──► 机器层：MD / JSON └── note → > **注意** 引用块 └── 写入 admonition-type 元数据字段 └── 与父级 <li> 步骤同 chunk 或显式 parent_id

类型语义在发布转换环节完成，而非依赖模型从图标猜测。

改进路径

场景建议优先级
环境准备 note（set_env.sh）规则 1–4：补类型 + MD 引用块P0
全站 note / warning 图标规则 3：aria-hidden + 文本前缀P0
嵌套在步骤列表内切片保留 li 边界 + 类型元数据P1
按类型检索chunk 索引 admonition-type 字段P1
