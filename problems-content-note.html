注意提示（Note）类型语义 正文可抓

注意提示类型语义指 note / warning / caution / tip 等提示级别对模型是否可识别——notebody 正文可获取，但装饰图标无文本。 以 环境准备 为例：模型不知道这是「注意」还是「警告」，也无法按类型过滤检索。

核心问题
  • 环境准备页 notebody 正文可入库（如 set_env.sh 说明），但提示类型语义丢失——图标 PNG 不产生可检索文本
  • 无 data-admonition-type 等结构化字段，RAG 无法按「注意 / 警告」过滤；LLM 引用时缺少 > **注意** 级别前缀
  • 嵌套在列表步骤内时，从属关系见 表格的结构语义；与 装饰图标 问题同类

问题实测

测试问题

读取 环境准备（CANN 9.0.0），安装 CANN 后需要执行什么命令设置环境变量？这条信息是普通正文还是「注意」类提示？能否只检索文档中的「警告」而不混入「注意」？

结论：正文可抓，类型语义缺失

提示正文能进入知识库，但类型不可识别。用户问「set_env.sh 怎么执行」时可召回正文；问「环境准备有哪些注意事项（注意级别）」时，chunk 中缺少类型标签，与正文段落难以区分。

注意提示语义对照

提示要素页面上入库后
notebody 正文set_env.sh 等可阅读已入库
提示类型（注意/警告）黄色框 + 图标传达完全丢失

与步骤从属关系嵌套在 <li> 内视管道而定

入库状态对照

入库环节状态说明
notebody 正文已入库set_env.sh 等可检索
提示类型标注完全丢失图标无文本语义
MD 引用块转换未执行无 > **注意** 前缀
装饰图标噪声或空白应 aria-hidden

解决方案

改进目标

让每条注意提示以带类型标签的结构化 chunk入库——正文可检索，类型可过滤（note / warning / caution / tip），LLM 引用时带 > **注意** 级别前缀，与所属步骤的从属关系保留。

改进措施

  • 必要data-admonition-type 标注：源码中标注 note / warning / tip / danger 等提示类型；
  • 必要补充文本类型前缀：渲染页中用「注意：」「警告：」等文字替代 note_3.0-zh-cn.png 装饰图标；
  • 必要机器层引用块（blockquote）：将提示转换为 Markdown 格式，如 > **注意** 正文内容，保留类型标识与正文；
  • 可选嵌套在 <ol><li> 内的提示，抓取时保留原始层级关系，禁止扁平化处理。

核心原则：类型语义先行入库——图标仅作装饰，类型与正文由文本承载。详见 亲和原则 · Note 类型。
