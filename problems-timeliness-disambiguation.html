多版本并存与消歧

昇腾文档站同时存在 8.x、850 商用、900 社区、9.1 beta 等多套 URL——缺乏消歧时，RAG 与模型生成都难以保证「最新版优先」。

结论

版本标识典型路径特征实测中出现场景
CANN 8.0 / 8.1 / 8.2 RC80RC、81RC1、82RC1、PDF 源DeepSeek 检索池主力
CANN 850 商用版canncommercial/850千问脚注、Claude 部分链接
CANN 9.0.0 社区版（900）CANNCommunityEdition/900三模型检索/生成均未稳定出现
CANN 9.1 beta910beta1Claude 检索、千问部分脚注
8.5 alpha850alpha001Claude 检索偶现

消歧失败的表现

  • 同一 prompt 下，不同模型引用不同世代的 Ascend C 文档
  • URL 路径中的版本号未进入 chunk 元数据，向量检索无法按版本过滤
  • 用户无法从回答中判断「这条命令适用于哪一版 CANN」
  • 知识库若整站抓取，旧版与新版的 bisheng 参数、API 名称同时可召回，加剧冲突

消歧方向（问题侧归纳）

措施作用归属
每篇文档 Front Matter 标注 version 入库时可过滤 version=CANN社区版 9.0.0 元数据字段规范
机器层声明 canonical URL（当前主推版本） 避免 8.x 与 900 并行入库无主次 llms.txt / 双轨交付
RAG 检索默认 version 过滤 + 用户显式指定版本 生成阶段优先召回 900 chunk 知识库集成
废弃旧版在 llms.txt 中标注 deprecated 爬虫与 Agent 不将旧版作默认入口 版本滞后问题 配套
与信息结构的边界
本页讨论多版本混淆的问题与消歧策略；具体字段 schema（doc_id、breadcrumb、applicable_devices）在 信息结构 · 元数据字段规范 展开，不在此重复。
