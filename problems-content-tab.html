隐藏的语义（Tab）

Tab 隐藏语义指被交互 UI 折叠、未进入默认抓取管道的正文——非激活 Tab 面板常被 display:none 隐藏。用户切换 Tab 能看到 bisheng / CMake 等分支内容，知识库可能只入库第一个 Tab，其余编译步骤与代码语义丢失。

抓取差
核心问题
  • 渲染页 /document/detail/ 将 HelloWorld「bisheng / CMake」编译方式做成 Tab UI，非激活面板被 CSS 隐藏——默认抓取可能只抓到 bisheng 分支
  • 源 HTML /doc_center/source/ 中两分支为同级顺序排列，源层较亲和；风险在渲染层与 RAG 管道消费渲染页时的隐藏截断
  • 全站渲染页约 34 处 display:none（含 Tab、折叠等），与用户可见内容存在系统性差异

测试问题

读取 HelloWorld（CANN 9.0.0），除了 bisheng 命令行编译，CMake 编译步骤和命令是什么？两分支的代码块是否都进入了知识库？

结论：非激活 Tab 语义未入库或截断

用户切换 Tab 能看到两分支，默认 RAG 管道可能只入库第一个。问「HelloWorld 如何用 CMake 编译」时，若抓取消费的是渲染页 DOM 且跳过 display:none 区域，知识库中没有 CMake 步骤 chunk 可召回。

1. 渲染层 Tab UI → 隐藏非激活面板

HelloWorld 页将「使用 bisheng 命令行进行编译」与「使用 CMake 进行编译」呈现为 Tab 切换。渲染层 CSS 含 .tab-hover .more-tab-item{display:none} 等规则，非激活 Tab 正文与代码不在默认可见 DOM 中。

<div class="tab-hover"> <!-- 默认可见：bisheng 分支 --> <pre>bisheng hello_world.asc --npu-arch=dav-2201 -o demo</pre> <!-- display:none：CMake 分支 --> <div class="more-tab-item" style="display:none"> <pre>cmake_minimum_required(VERSION 3.16)...</pre> </div> </div>

2. 源 HTML 层 → 顺序展开（较亲和）

若抓取 /doc_center/source/ 端点，bisheng 与 CMake 在源 HTML 中为同级 <li> 顺序排列，两分支均存在于源文件。问题在于多数 RAG 管道默认消费 /document/detail/ 渲染页（~224 KB），而非 4–11 KB 源 HTML。

3. 丢失的 Tab 语义清单（HelloWorld）

Tab 标签丢失或截断的语义
使用 bisheng 命令行进行编译通常作为默认 Tab 可入库（仍受行号污染影响，见代码语义）
使用 CMake 进行编译CMakeLists 内容、cmake / make 步骤——非激活时可能完全丢失

4. 端点差异 → 同一页两种入库结果

抓取端点Tab 语义状态说明
/doc_center/source/两分支均存在源层顺序展开，无 Tab 隐藏
/document/detail/ 渲染页可能只入库默认 Tab非激活面板 display:none
转 Markdown / Reader 管道取决于是否跳过隐藏节点多数管道忽略隐藏 DOM

入库状态对照

入库环节Tab 语义状态说明
默认 Tab（bisheng）部分可抓正文与命令可入库
非激活 Tab（CMake）完全丢失渲染层隐藏，管道跳过
源 HTML 顺序展开已入库需显式消费 source 端点
Tab 标签文本可能丢失未结构化进 chunk 元数据
机器层全展开（TAB-03）源站缺失发布环节未扁平化输出

改进目标

让每个 Tab 面板的正文与代码以独立文本 chunk进入知识库——检索「CMake 编译 HelloWorld」「bisheng 命令参数」时均能召回，不要求用户在线切换 Tab，要求机器层事先全量展开。

改进措施

一、内容侧：Tab 全量文本化（P0，治本）

核心原则：Tab 内容先行入库——每个 Tab 须有可读标签，正文在源 HTML 中顺序展开。详见 亲和原则 · Tab 语义。

做法入库效果
1 源 HTML 中所有 Tab 面板完整存在，不依赖 JS 懒加载（TAB-01） 抓取不遗漏任一 Tab 正文
2 每个 Tab 有明确文本标签（TAB-02） chunk 可区分「bisheng」与「CMake」
3 机器层全部展开，用 H3 标注各 Tab 标题（TAB-03） 扁平 MD 中两分支均可检索
4 禁止在源 HTML 用 display:none 隐藏非默认 Tab（TAB-04） 源层与机器层一致，无隐藏截断

HelloWorld 编译分支改造示例

❌ 当前：渲染层 Tab 隐藏

<!-- 仅默认 Tab 可见，CMake 在 display:none 内 --> <div class="tab-card">...bisheng...</div> <div class="more-tab-item" style="display:none">...cmake...</div>

知识库 chunk：可能仅有 bisheng 命令，无 CMake 步骤。

✅ 改造后：源层 + 机器层全展开

<h3 id="compile-bisheng">使用 bisheng 命令行进行编译</h3> <pre><code class="language-bash">bisheng hello_world.asc --npu-arch=dav-2201 -o demo</code></pre> <h3 id="compile-cmake">使用 CMake 进行编译</h3> <pre><code class="language-cmake">cmake_minimum_required(VERSION 3.16)...</code></pre>

知识库 chunk：可分别检索「bisheng 编译」「CMake 编译 HelloWorld」。

机器层 Markdown 输出要点

### 使用 bisheng 命令行进行编译 ```bash bisheng hello_world.asc --npu-arch=dav-2201 -o demo ``` ### 使用 CMake 进行编译 ```cmake cmake_minimum_required(VERSION 3.16) ... ```

二、架构侧：双轨交付 + 端点优先级

双轨交付——人类层保留 Tab 交互，机器层消费源 HTML 或预展开 MD：

HTML 源（doc_center） │ ├──► 人类层：Tab UI + 交互切换（体验不变） │ └──► 机器层：MD / JSON + llms.txt └── 优先消费 /doc_center/source/（4–11 KB） └── 各 Tab 扁平为 H3 + 正文 chunk └── 禁止依赖渲染页 display:none 区域

RAG 管道应声明抓取端点；Tab 语义在发布环节全量展开，而非检索时模拟点击 Tab。
