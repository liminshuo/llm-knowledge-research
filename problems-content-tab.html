隐藏的语义（Tab）

Tab 隐藏语义指被交互 UI 折叠、未进入默认抓取管道的正文——非激活 Tab 面板常被 display:none 隐藏。用户切换 Tab 能看到的内容，知识库可能只入库默认 Tab，其余面板正文与代码语义丢失。

抓取差
核心问题
  • 全站渲染页广泛存在 tab-hover / more-tab-item 等 Tab 组件，非激活面板可被 CSS 隐藏——默认抓取可能只抓到默认 Tab
  • 四页实测中 HelloWorld 的 bisheng / CMake 两分支以嵌套列表并列默认展示，非 Tab 隐藏案例；该页风险在代码语义（行号污染）等维度
  • 全站渲染页约 34 处 display:none（含 Tab、折叠等），与用户可见内容存在系统性差异

测试问题

读取含 Tab 切换的昇腾文档章节，非激活 Tab 面板内的正文与代码是否进入了知识库？再读 HelloWorld（CANN 9.0.0）：bisheng / CMake 两分支在渲染页上是否默认均可见？

结论：非激活 Tab 语义未入库或截断

全站 Tab 组件存在隐藏非激活面板的风险，但 HelloWorld 不是该场景的实测样本。该页「使用 bisheng 命令行进行编译」与「使用 CMake 进行编译」以嵌套列表并列默认展示，两分支在渲染页上均可见；CMake 步骤能否召回，取决于正文是否入库及代码语义是否劣化，而非 Tab 隐藏。

1. HelloWorld 实测 → 列表并列，非 Tab 隐藏

HelloWorld（CANN 9.0.0） 在「完成代码实现后，可以通过两种方式，对上述代码进行编译」下，以两个嵌套列表项展示 bisheng 与 CMake 分支——无 Tab 切换、无折叠面板，两分支正文与命令在默认渲染页上均可直接阅读。

2. 全站 Tab 组件 → 隐藏非激活面板

昇腾文档渲染层 CSS 含 .tab-hover .more-tab-item{display:none} 等规则。在实际采用 Tab UI 的章节中，非激活面板正文与代码可能不在默认可见 DOM 中，默认管道跳过 display:none 区域时等价于完全丢失。

<div class="tab-hover"> <!-- 默认可见：第一个 Tab 面板 --> <div class="tab-panel-active">...默认分支正文...</div> <!-- display:none：非激活 Tab 面板 --> <div class="more-tab-item" style="display:none"> <pre>...隐藏分支正文...</pre> </div> </div>

改进目标

让每个 Tab 面板的正文与代码以独立文本 chunk进入知识库——检索「CMake 编译 HelloWorld」「bisheng 命令参数」时均能召回，不要求用户在线切换 Tab，要求机器层事先全量展开。

改进措施

一、内容侧：Tab 全量文本化（P0，治本）

核心原则：Tab 内容先行入库——每个 Tab 须有可读标签，正文在源 HTML 中顺序展开。详见 亲和原则 · Tab 语义。

做法入库效果
1 源 HTML 中所有 Tab 面板完整存在，不依赖 JS 懒加载（TAB-01） 抓取不遗漏任一 Tab 正文
2 每个 Tab 有明确文本标签（TAB-02） chunk 可区分「bisheng」与「CMake」
3 机器层全部展开，用 H3 标注各 Tab 标题（TAB-03） 扁平 MD 中两分支均可检索
4 禁止在源 HTML 用 display:none 隐藏非默认 Tab（TAB-04） 源层与机器层一致，无隐藏截断

多分支内容改造示例（以 HelloWorld 编译步骤为例）

❌ 风险形态：Tab UI 隐藏非默认面板

<!-- 仅默认 Tab 可见，其他分支在 display:none 内 --> <div class="tab-card">...默认分支...</div> <div class="more-tab-item" style="display:none">...隐藏分支...</div>

知识库 chunk：可能仅有默认 Tab 正文，非激活面板完全丢失。

✅ 改造后：源层 + 机器层全展开（HelloWorld 当前列表形态已接近此目标）

<h3 id="compile-bisheng">使用 bisheng 命令行进行编译</h3> <pre><code class="language-bash">bisheng hello_world.asc --npu-arch=dav-2201 -o demo</code></pre> <h3 id="compile-cmake">使用 CMake 进行编译</h3> <pre><code class="language-cmake">cmake_minimum_required(VERSION 3.16)...</code></pre>

知识库 chunk：可分别检索「bisheng 编译」「CMake 编译 HelloWorld」。

机器层 Markdown 输出要点

### 使用 bisheng 命令行进行编译 ```bash bisheng hello_world.asc --npu-arch=dav-2201 -o demo ``` ### 使用 CMake 进行编译 ```cmake cmake_minimum_required(VERSION 3.16) ... ```

二、架构侧：双轨交付 + 端点优先级

双轨交付——人类层保留 Tab 交互，机器层消费源 HTML 或预展开 MD：

HTML 源（doc_center） │ ├──► 人类层：Tab UI + 交互切换（体验不变） │ └──► 机器层：MD / JSON + llms.txt └── 优先消费 /doc_center/source/（4–11 KB） └── 各 Tab 扁平为 H3 + 正文 chunk └── 禁止依赖渲染页 display:none 区域

RAG 管道应声明抓取端点；Tab 语义在发布环节全量展开，而非检索时模拟点击 Tab。
