表格语义化

用 caption、th、scope 表达表格的标题与行列关系，并把嵌在单元格里的接口列表独立出来，避免规格表结构在入库后劣化。 读的懂 · 序号 7 · 对应 问题论证 · 表格的结构语义。

设计UI调整

调整建议

  • 符号替换规范：建立表格内容写作规范，明确禁止使用仅靠形状表达含义的符号，所有状态必须用完整文字表达，纳入内容审核流程。
  • 表格标题文案交付：每张表格交付时同步提供 <caption> 文案，格式为"表N 描述性标题"，如"表1 Ascend C Add算子设计规格"，禁止使用"表格1""数据表"等无意义文字。
  • 复杂表格结构标注：复杂规格表（如含 I/O 子表、合并单元格、多级表头）在设计交付标注中明确：哪些单元格是表头（用 <th>），哪些是数据（用 <td>）；表头的作用域方向（scope="col" 或 scope="row"）；接口列表区域标注为独立列表结构，不拆成伪数据行。

文档内容调整

调整建议

  • 符号替换：表格单元格中禁止使用仅靠形状表达含义的符号，如 ✅、❌、-、N/A 等，所有状态必须使用完整的文字表达，如"是/否"、"支持/不支持"。 b.
  • 结构化标题：表格必须使用 <caption> 标签提供表格标题/摘要，列名称必须使用 <th> 标签。 c.
  • 作用域：<th> 标签应尽可能指定 scope="col" 或 scope="row"。

前端调整

调整建议

  • 表格完整语义结构实现：所有表格使用完整语义结构，<caption> 写入表格标题，<thead> 包裹 <th>，<th> 指定 scope，<tbody> 包裹数据行。
  • 复杂规格表 I/O 子表实现：I/O 子表的 name / shape / data type / format 列必须使用 <th> 表头，禁止用样式伪装成表头的 <td>；行级表头使用 scope="row"。
  • Chunk 切片管道追加规则：<caption> 内容作为表格 chunk 的标题元数据；<th scope="col"> 内容作为列名前缀，拼接到每个数据单元格；接口列表（<ul>）与所属表格绑定为同一 chunk，不拆分；优先使用 Markdown 副本入库，HTML 表格作为降级来源。

调整示例

1. 完整语义 HTML 表格

Before · 无语义表格

<table>
  <tr><td>name</td><td>shape</td></tr>
  <tr><td>x</td><td>(8,2048)</td></tr>
</table>

After · 完整语义结构

<table>
  <caption>表1 Ascend C Add算子设计规格</caption>
  <thead>
    <tr><th scope="col">name</th>
        <th scope="col">shape</th></tr>
  </thead>
  <tbody>
    <tr><td>x</td><td>(8, 2048)</td></tr>
  </tbody>
</table>
