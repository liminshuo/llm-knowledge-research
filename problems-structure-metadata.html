元数据字段规范

元数据回答的不是「正文写了什么」，而是这篇 chunk 是谁、属于哪一版、在知识体系哪一节——RAG 检索与过滤的前置条件。 本页论证：版本、breadcrumb、doc_id 等在页面上隐含存在，入库后未标准化为 chunk 字段，导致无法按版本过滤、消歧同名章节、稳定溯源。

核心问题
  • 页面有据、入库无情：「什么是 Ascend C」在 900 / 850 / 910beta 下 <title> 均含版本与章节路径，但无 JSON-LD / Front Matter；version、breadcrumb、doc_id 不进 chunk 元数据。
  • 同题异版不可分：同一 atlas_ascendc_map_10_0002 对应三套 URL，正文高度相似；无 version 字段时向量检索无法排除旧版。
  • 关系语义未结构化：设备型号、上下篇、Tab/Note 类型等可见但未字段化——检索只能做全文相似度，不能做字段约束。

测试问题

正文已进入向量库之后，能否回答：

  • 这条 chunk 适用于哪一版 CANN？
  • 「环境准备」属于入门教程还是软件安装？
  • 引用能否稳定回溯到唯一 doc_id？

若三者皆否，说明缺的是元数据字段，而非更多正文。

页面有据 · 入库未结构化

以 atlas_ascendc_map_10_0002 为例（hiascend-metadata-probe.md）。

信息页面上入库后
version ✅ URL …/900/… + title「CANN社区版9.0.0」 ❌ chunk 无 version 键
breadcrumb ✅ 压缩在 <title> 字符串 ❌ 未拆成数组，无法消歧
doc_id ✅ URL 文件名 ❌ 未写入 chunk
applicable_devices ✅ 正文列出 Atlas A2/A3 ❌ 无结构化列表
JSON-LD ❌ 实测 0 条 — 无标准头信息可继承
「未结构化」入库态
见 亲和原则 · IA 元数据字段一览：页面上有，但未变成可检索元数据。

同题异版 · 无字段则不可分

路径版本<title> 版本串（实测）
900 社区版…CANN社区版9.0.0…
850 商用版…CANN商用版8.5.0…
910 beta…CANN社区版9.1.0-beta.1…

三版 chunk 语义相近，无 version 字段时 RAG 无法默认「只取 900」。

下游失败印证

现象实测表现
脚注版本混杂 千问 [^10] 将「什么是 Ascend C」指向 850 商用（千问-检索网页.md）

论证链
机器入口 决定抓哪条 URL → 本文论证入库须带哪些字段 → 知识库集成 用元数据做过滤与溯源。

改进目标

每篇文档、每个 chunk 入库时附带可检索、可过滤的结构化字段——使 RAG 能按版本、章节路径、设备型号约束召回，引用可稳定映射到 doc_id。

改进措施

一、页面级 Front Matter（P0）

转换管道从 source HTML 提取并注入 YAML 头信息。每篇文档的机器层标准头信息：

字段作用
version版本过滤、多版本消歧
doc_id稳定引用、跨页去重
breadcrumb章节路径、消歧同名页
prev / next上下篇与学习顺序
applicable_devices按设备型号过滤
source_url / human_url机器层 vs 人类层双轨标注
--- doc_id: atlas_ascendc_map_10_0005 title: HelloWorld product: Ascend C算子开发 version: CANN社区版 9.0.0 language: zh-CN breadcrumb: - Ascend C算子开发 - 入门教程 - 基于SIMD编程 - 快速入门 - HelloWorld keywords: [HelloWorld, 核函数, bisheng, CMake] applicable_devices: - Atlas A2 训练系列产品 - Atlas A3 训练系列产品 source_url: https://www.hiascend.com/doc_center/source/... human_url: https://www.hiascend.com/document/detail/... ---

轻量 IA（P1）

提供页面级元数据，而非全站 282 项导航树：

  • breadcrumb：消歧 + 定位章节
  • prev / next：支持多跳推理与学习顺序
  • version：锁定 CANN 9.0.0，避免版本混淆
  • keywords / applicable_devices：精准检索过滤
实施方式
机器层 Front Matter 输出完整字段；人类层可保留现有可视面包屑，并可选 JSON-LD breadcrumb。

二、chunk 级字段（P1）

切片时把组件类型写入 chunk 元数据，衔接语义维度页规则：

字段关联维度
admonition-type注意提示类型
tab_labelTab 分支
code_language / filename代码语义

三、知识库集成与检索策略（P0）

文档源（doc_center/source） │ ▼ 转换管道（HTML → MD + Front Matter） │ ├──► 向量库（Embedding + 切片索引） │ └── RAG 检索（语义搜索 + 元数据过滤） │ └──► JSON API（Agent Tool Calling）
  • 按 H2/H3 边界切片 — 避免截断代码块
  • 元数据前置 — 每片附带 breadcrumb、version、keywords
  • 表格不拆分 — 整张表作为一个切片单元
  • 注意提示与上下文绑定 — 提示不脱离所属步骤
策略依赖字段示例
版本过滤versionfilter(version="CANN社区版 9.0.0")
设备过滤applicable_devicesAtlas A2 专属算子
breadcrumb 消歧breadcrumb入门教程/环境准备 vs 软件安装/环境准备
关键词增强keywords核函数、bisheng、Tiling、SIMD

四、与转换管道衔接（P1）

元数据在 转换管道 第 6 步注入——从 doc_center/source 解析 title 路径、URL 版本段、设备列表，输出标准 Front Matter，而非依赖渲染页剥壳猜测。
