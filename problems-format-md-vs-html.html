Markdown vs HTML

纯 Markdown 与 HTML 渲染页在知识获取场景下的对比。

要点一：Markdown 与 HTML，哪个对大模型更友好？

结论（知识获取场景）
在大模型读取、抓取、RAG 入库场景下，纯文本 Markdown 比 HTML 更友好，读取效率更高。 前提：必须是真正的 Markdown 源文件，而非带 .md 后缀的 SPA 渲染页。
维度纯 MarkdownHTML（渲染页）评判
信噪比 标题、列表、代码块均为显式文本标记，几乎无布局噪声 含 class、Vue 指令、导航壳、Cookie 横幅、282 个 o-link MD 胜
Token 效率 同内容 Token 消耗低，结构可预测 同内容约为 MD 的 2–4 倍；昇腾实测单页 200KB+ MD 胜
解析稳定性 # ## - ``` 边界清晰，RAG 切片可靠 依赖 DOM 解析，标签嵌套复杂，hidden/tab 内容易遗漏 MD 胜
抓取依赖 静态文件，无需 JS 渲染 Nuxt SPA，161 处 v-if，静态爬虫可能不完整 MD 胜
人类交互 纯文本，无品牌视觉、Tab、热区导航 支持图片热区、折叠、Tab、侧边导航 HTML 胜

为什么 Markdown 读取效率更高？

  • 结构即文本 — 标题层级（#）、列表（-）、代码块（```）直接写在正文中，模型无需从 DOM 树反推语义
  • 无壳层污染 — 不包含全站导航、页脚、广告、JS 变量，有效 Token 几乎全部用于正文
  • 切片友好 — RAG 按 H2/H3 边界切分时可精确定位；HTML 中同级语义可能散落在 div/span 中
  • 行业共识 — llms.txt 规范 明确推荐 Markdown 作为 LLM 友好格式；Anthropic 文档站亦提供 /llms.txt 索引
补充 · Anthropic 的另一面观点
Anthropic Claude Code 工程师 Thariq Shihipar 在 《The unreasonable effectiveness of HTML》 中主张 HTML 优于 Markdown——但讨论的是 Agent 输出给人看（计划、Spec、Review），而非文档抓取入库。 两个场景结论相反，不可混用。
